# 算力分工、重试和缓存

这是一份运行策略，不是自动模型切换程序。本包不含供应商 API key、模型调用 SDK 或收费路由。
Agent 平台支持多模型时按下表分工；不支持时，把确定性步骤作为工具执行，不再让当前模型反复重写代码。

| 阶段 | 默认执行方式 | 何时升级视觉推理 |
| --- | --- | --- |
| 初次范围/主造型/遮挡判断 | 一次较强视觉模型，或人工 | 这是主要推理投入，不应以通用盒子模板跳过 |
| 观察转 spec | 已确认观察 + 普通模型；schema 校验 | 关键对象的关系仍未说明 |
| 参数合法性/归属/未使用参数检查 | 固定代码，不调用模型 | 程序报错后提供错误摘要和相关局部数据 |
| 几何生成与 .blend 保存 | 固定代码 | 遇到未支持的关键几何原型，单独开发和测试 |
| 相机优化 | 对既有对应点做数值拟合 | 对应点、投影类型或结构假设错误 |
| masks/轮廓/点误差计算 | 固定代码 | masks 的语义归属不确定；不能用计算掩盖错误标注 |
| 小幅改宽度/位置/材质 | 组件 ID + 参数 patch + 重建 | 指令有歧义，或改变构件连接关系 |
| 最后语义和第二视角复核 | 一次较强视觉模型/人工 | 仍有关键差异时，禁止直接 pass |

“首次理解 + 最后复核”是理想的强模型投入位置，不承诺每张图只调用两次。复杂遮挡可能需要追加局部审查。
看图裁切仅用于更精确判断，不能替换原图坐标系。不要每次都把全部源码和整张多视角大图重复输入。

## 低成本迭代

先低采样、接近原图分辨率进行结构对拍；先不投入昂贵产品资产、玻璃材质和高分辨率渲染。
每一轮记录 iteration、spec_hash、camera_hash、问题 ID、改了什么、改善了哪些指标、哪些检查仍失败。
先做最多 3 轮；连续 2 轮进展低于记录的容差，停止盲目数值微调，向视觉模型提交原图裁切、同位置渲染、少量参数及误差摘要。
这些预算是建议的运行控制，并非本包已部署的自动多模型调度器。

## 缓存已实现的部分

`common.fingerprints(spec)` 计算分析、几何、相机、渲染、验收的版本指纹。
`common.cache_valid(manifest,key,root)` 必须同时检查 complete 状态、相同 key、全部输出存在、文件非空、SHA-256 匹配。
旧预览、执行失败的临时输出和参数修改前的 QA 不能重用。

`boothctl patch` 产出失效阶段摘要。几何变更将 camera.fit_status 改为 unfitted；材质变更不改变几何指纹。
当前 Blender 执行脚本仍完整重建场景，没有对象级增量更新。缓存函数是供调用方使用的原语，未连接自动任务调度服务。
即使完整重建，重复创建网格、改尺寸、保存/渲染也无需 LLM 重新写代码；消耗的是本地 Blender 计算资源。

不得在未经实际测量时宣传节省 80% token、固定成本或几分钟完成。应由真实运行日志统计调用次数、token、CPU/GPU 时间和成功率。

缓存接入注意：当前 fingerprints 的输入是 spec 与脚本代码。调用方若缓存标注、外部素材或 mask，必须把这些文件的实际 hash 加入自己的缓存 key；不要仅凭 spec 指纹复用外部文件变化后的结果。assess 每次重新读取、计算并绑定实际文件，没有自动跳过这一步。
