# 旧候选失败案例与 v2 回归边界

本页记录一次早期失败的重建暴露的问题，以及 v2 为此设立的防线。原始失败案例来自一张客户图，不随仓库发布；测试改用合成示例
`examples/regression/`（由 `tests/make_regression_example.py` 生成，所有尺寸都是虚构的），保留同样的“未完成候选”特征。
`tests/` 和 `examples/regression/` 只在源码仓库里；运行时 zip 不含它们，只附带 `examples/regression/annotations.template.json`。

## 合成示例

- `examples/regression/reference.png`：合成画面，640×480。
- `examples/regression/legacy_proxy.png`：画幅不同的旧版预览（合成），用来证明比较时会拒绝不同画幅。
- `examples/regression/legacy_spec.json`：旧格式参数（没有 `schema_version`），用来证明旧格式会被拒绝。
- `examples/regression/candidate_spec.json`：v2 候选。相机未拟合、关键不确定项未关闭，用来证明系统不会把“能运行的代理”当成完成品。

## 已查明的旧问题

- 上方楣框用四个独立盒子拼接，每件各自倒角，不是显式构造的完整圆角矩形环。
- 旧 spec 的 `corner_radius_visual` 没有被建模脚本读取，参数说明与实际几何脱节。
- 门架由两腿和顶部盒子拼接，不足以保证原图的连续转弯关系。
- 旧脚本创建了 12×12 m 的渲染地面，与“只建展台本体”的范围冲突。
- 旧代理预览与原图画幅和机位不同，没有证据支持它是同机位验收图。

## 本版对应防线

- 连续圆角环和门架由显式内外轮廓构造，独立测试 watertight、绕序、连通性和开口。
- 所有 params 都必须是对应构件真正读取的字段；未使用的“visual”参数直接拒绝。
- 源 spec 和已生成场景同时检查范围；渲染装置只允许相机和灯，不按名字猜测合规。
- 原图与验收图尺寸不同直接拒绝比较，不偷偷缩放或做局部扭曲配准。
- 没有 `.blend` 原生重开、真实渲染、已审核 masks 或视觉检查记录时，禁止交付完成态。

## 需要避免的另一种过拟合

不能因为某张图用了圆角白色造型，就把所有新展台都做成同样的环和门架。结构是否共用实体要靠裁切观察和候选对拍，不能把猜测当成真值。
图案与产品可以放在主结构匹配之后处理，但不应永久省略。
